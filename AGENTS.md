# lifi-contract-types

TypeScript typings (TypeChain, ethers v5) for the LI.FI Solidity contracts, plus the diamond ABI. Other
LI.FI repos depend on it by git tag (`vX.Y.Z`, `vX.Y.Z-beta*`). The package name in `package.json` is
`lifi-contract-typings`.

## Generated content: do not hand-edit

Everything under `src/` and `dist/` is generated by the "Types Bindings" workflow in
[lifinance/contracts](https://github.com/lifinance/contracts/blob/main/.github/workflows/types.yaml):

- It runs `bun typechain` in `contracts`, deletes `src/` here, copies the new bindings in, copies
  `diamond.json` into `dist/`, runs `bun install && bun run build`, bumps `version` in `package.json`,
  commits `actions: new contracts version <version>`, tags `v<version>` and pushes.
- Pushes to `contracts` main produce release tags; `contracts` PRs with the `requires-types` label produce
  `-beta` tags.

So a fix to a type belongs in the Solidity source or the workflow in `contracts`, not here. Manual edits to
`src/` or `dist/` are overwritten by the next run. Only the hand-maintained files below are safe to change.

## Layout

- `src/`: generated TypeChain types, one `<Contract>.ts` per contract, `<File>.sol/` folders for files
  with several contracts, `factories/` with the `__factory` classes, `index.ts` re-exporting all.
- `dist/`: compiled JS and `.d.ts`, committed (the package is consumed from git, not npm), plus
  `dist/diamond.json` (the diamond ABI).
- Hand-maintained: `package.json` (dependencies, `exports` for deep imports), `tsconfig.json`,
  `README.md`, `.github/dependabot.yml`, this file.

## Commands

```bash
bun install
bun run build      # tsc into dist/, then copy src/**/*.d.ts into dist/
```

`bun run compile` and `bun run copy-dts` are the two halves of `build`. There are no tests and no linter;
`tsc` passing is the check. The README still shows `yarn`; the publishing workflow and `bun.lock` use Bun.

## Env

None. The repo reads no environment variables.

## Conventions

- Adding a deep import path (like `./GasZipFacet`) means adding it to `exports` in `package.json`; the
  file itself comes from the generator.
- Do not bump `version` by hand: the workflow derives the next tag from the latest one.
